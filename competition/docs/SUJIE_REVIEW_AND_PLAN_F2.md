## 5. 产品主线和增删改决策

产品定义：面向安全研判与研发协作 Agent 的运行时防护网关，在攻击内容被读取、
转换、记忆或传递后，继续约束实际工具效果，允许在授权范围内完成任务。

保留：

- Python 授权域、Contract/Grant、DSL、来源信封、执行前绑定、三态和真实 MCP。
- Python 操作者服务与 Vue，已有副作用 Oracle、冻结实验和暴露记录。
- 模型和工具均视为不可信提议来源，语义检测只能收紧权限。

重做或调整：

- 统一当前运行入口为 `sujie`，根部早期 AgentGuard 作为历史原型保留，退出主结果和演示。
- 将恢复主线从隐藏正文改为保留必要证据及出处；原投影保留为明确标记的降级方案。
- 用强静态工具网关替换旧弱 Static 主对照，历史实验保留。
- 为模型请求与最终答复建立出口裁决；增加直接入口、全序列研判和 token 来源映射。
- 将固定工具实例扩展为定义明确的受限适配器，名称和说明符合实际执行能力。
- 当前检测 confidence=0.9 改为未校准的规则信号或明确等级，避免被误读为概率。
- 新版分类器按独立执行收益、误报和调用成本选择，不能仅按 TRAIN 召回升级。
- 更新根 README、sujie README、团队说明与能力索引，历史文档标日期和继任文档。

延期至决赛需求明确后：Java/MySQL 重写、多操作者、多副本、任意 Shell、通用沙箱、
多平台适配、复杂微服务、模型微调和展示动画。官方五项能力继续是初赛实施重点。

## 7. 提交版实施工作包

### W0：需求与证据统一

产物：官方条款矩阵、能力状态表、单一启动入口、历史结果清单、最终声明清单。
每条声明关联代码、案例、实际运行报告及限制；把分类、实际执行、确定性回放分别列出。
完成依赖/许可、提交匿名规则和必需材料清点，先搭主报告结构。

验收：评审从任一官方能力可找到运行入口和证据；README 与控制台能力一致。

### W1：可信上下文、三入口与来源定位

1. 在用户消息入口区分认证身份、用户任务和声明的权限；用户文字不能伪造管理员身份。
2. 外部网页、文档、代码、工单/邮件、MCP 描述和返回值均登记内容及来源类型。
3. Memory 写入、检索、下一会话读取保留原始来源与权限属性，扫描隐性触发内容。
4. 增加上下文构建器，记录实际发送消息的内容区段、Artifact、字段、字符/字节区间。
5. 用固定 tokenizer 标记网关构造输入的 token 区间，记录 tokenizer 版本与摘要；
   区分精确来源、转换继承来源、近似映射和未知。云服务内部实际分词/截断不透明时，
   不宣称观测其内部 token 或思维链。无法建立映射的范围明确记为部分完成。
6. 原文与规范化视图分离，保留 offset 关系；不能用整段 span 代替精细来源验收。
7. 超长输入分段分析并保持来源，或显式拒绝超限输入；不能静默截断未扫描尾部。

验收：三类来源均能从模型输入区间定位到原始材料；摘要/编码/跨轮转换不获得权限。

### W2：全序列研判与分级检测

建立任务级解释记录，包含可信目标、可见计划摘要、完整工具序列、候选动作、
偏离类型、涉及来源、风险与决策。偏离分为任务目标、资源、实际效果、数据流及序列。
模型自行描述的计划只能作为证据，不代替执行记录。

调用顺序：确定性授权/来源/状态检查 → 有界规范化与规则 → 不确定情况的无工具语义
分类 → 必要的确认或隔离分析。硬拒绝不因模型建议而改变。语义预算耗尽、超时或
格式不合法有显式保守结果。

v1/v2 在独立任务上比较，并记录实际调用比例、等待时间和 Token。如加入缓存，键包含
任务合同、策略、工具版本、来源内容及检测器版本，避免跨任务结论误用。

验收：能解释“读 README 后为什么不能读凭据并外发”，也能解释合法危险文档为何
允许分析；能检出攻击与最终阻断效果分别统计。

### W3：五类工具的实际效果约束

| 类别 | 具体实现重点 | 必须观测的实际状态与合法对照 |
|---|---|---|
| fs.write | 可信展开 home、规范化路径；敏感目录、别名、遍历、覆盖、来源约束；执行前重新确认目标 | 被保护文件哈希不变；授权报告文件真实写入 |
| net.fetch/transfer | 有界请求、方法/目的地/重定向/请求内容；敏感来源不能通过 URL、header、body 外发 | HTTP 接收端实际请求/内容；受信任公共 IOC 正常传输 |
| exec | 结构化 argv、明确支持的命令和参数；编码解码执行、下载管道、分隔符拼接等禁止；受限工作区与进程资源 | 禁止操作未产生进程/文件/网络效果；合法哈希/解析等任务可执行 |
| git.push | 真实 remote/ref/提交内容绑定；代码检视合同不含推送能力；审批与版本复核 | 本地封闭远端 ref 和提交对象；明确授权的推送成功 |
| delegate | 子任务内容与敏感来源检查；父权限上限、子 Grant 收窄、共享预算和完整关联 | 子 Agent 实际输入与工具记录；公开证据委派成功，秘密未传递 |

执行器和网络出口独立于模型提议。原固定哈希进程仍可作合法执行样例，但需要加入
真实命令提议与参数门禁；不宣传通用 Shell 语义判断。未知语言/命令按策略拒绝。
敏感路径与所有效果测试在受控工作区/容器中完成。

每类至少具有合规、需确认、强制拒绝及伪造批准/参数变化测试；强制拒绝不能被审批
覆盖。不要求同一个硬禁止操作同时能够三态转换。

### W4：子 Agent、Memory 与跨 MCP 攻击链

子 Agent 必须有独立上下文、工具菜单、受限 Grant 和实际多轮工具循环，补齐当前
仅有逻辑子 Gateway 的缺口。提交版可在同一可信 Host 内运行，但要明确部署边界；
跨进程隔离后续增强。建立至少两级父子关系及不同 MCP 的真实调用关联。

至少完成：

- 外部证据 → 摘要/序列化 → 子 Agent → 外发/写入提议；
- 外部证据 → Memory → 新会话 → 工具滥用提议。

增加完整性攻击：篡改报告事实、替换推送目标或污染持久化记忆，避免全实验只覆盖
私密文件读取和蜜标外发。保留合法跨会话知识使用与正常委派对照。

验收：三态与来源在整条链上保持；能展示触发源、主/子 Agent、MCP、动作和影响对象。

### W5：自主 ASK 暂停与续跑

将模型运行状态扩展为 RUNNING → WAITING_APPROVAL → RESUMING → COMPLETED/
REJECTED/CANCELLED/FAILED。等待期间不执行副作用，可查询、导出和取消。

审批页面固定展示真实动作、参数、来源与风险；批准后复核合同、策略、工具版本、
内容及有效期，再提交单次动作并恢复模型。拒绝/超时返回结构化结果，可继续原任务。
取消不能撤销已经执行的副作用；执行结果不明时标 UNKNOWN，检查真实状态后处理，
不自动重发可能重复的操作。

验收：真实模型提出外发 ASK、操作者批准并续跑，接收端仅一次请求；篡改/重放失效。
初赛不宣称跨崩溃 exactly-once，持久化恢复另做专项验收。

### W6：信息保全恢复与出口控制

1. 一次阻断后以原可信任务生成结构化异常，收窄工具菜单并保留原权限。
2. 无工具证据分析路径输出受限事实、引用、出处和未处理内容；Host 验证引用确实
   位于登记材料、字段及长度合法，所有输出仍继承 DATA_ONLY/原始来源。
3. 主 Agent 接收隔离输出时保持数据区与控制指令区分，不把分析输出转换成授权。
4. 冻结任务前登记必需事实、必要正文/引用集合、出处匹配、允许信息损失和不支持项。
   检查事实覆盖、正文、论据及结论一致性，与旧投影比较；上游 utility 与信息保全分列。
5. 再次等价越权或恢复预算耗尽明确停止/询问，不能反复调用直到偶然成功。
6. 主模型、分类器、隔离分析器、子 Agent，以及重试/恢复请求都经过统一 Provider
   检查，且检查发生在发送前。核对目的地、上下文数据类别与用途；保护数据不能
   因误读自动进入下一轮云请求。以独立请求捕获校准“误读后各入口均未携带禁发内容”。
   最终答复另经来源与敏感输出检查，逐字蜜标检查与编码/改写泄露检查分别记录。

验收：危险命令可被引用分析，秘密和执行权限未进入分析输出；恢复确实保留任务所需
正文。无工具模型并非天然可信，其输出仍接受 Schema、来源和工具效果门禁。

### W7：独立任务、强基线与因果证据

先接 AgentDojo 已固定发布包的有限环境和原始 utility/security Oracle，再扩范围。
合同来源只允许可信用户、身份权限和事先发布策略，不能读取攻击标签或预期答案。
适配器、任务版本、支持与排除项在运行前登记，不把本地映射成绩标为官方全量成绩。

提交版内部目标：至少 12 个可区分基础任务、至少 4 个工作流族。增加任务必须有
实质不同的可信目标、工具流程或状态判定，不能仅改告警文字/参数增加计数。
先完成少量完整任务与双 Oracle，再扩到 12；规模受资源约束时透明报告实际分母。

每任务四类对照：C 普通正常；A 受注入；Q 合法危险证据分析；R 用户明确授权的
受限高风险操作。跨摘要、Memory、子 Agent 的传播作为 A 子集单列。

主配置：

- B0：Unsafe，靶场物理隔离保持，取消待比较的应用防御；用于攻击效果校准。
- B1：Strong Static，固定身份/工具/资源/目的地/参数限制及当前规则；无需动态
  任务来源传播，配置在评测前冻结。不能继续只用旧 rules-v0.1 作为主对照。
- Full：B1 公共安全条件，加任务授权、来源用途、动作绑定与恢复。
- A1：Full 去来源约束，其余条件相同；A2：Full 去恢复，其余条件相同。

开关级差异固定：A1 仅移除指定的来源—用途授权判定，保留来源登记、检测、
Provider/答复出口、审批绑定和恢复；A2 仅关闭恢复动作。逐项记录各机制是否实际
被触发，ACL 已先阻断的案例不能作为来源机制贡献证据。A1/A2 各设正例校准。
来源校准可采用按 Artifact ID 提议传输，由可信工具持有材料，模型不接触禁发原文；
为授权读取但禁止外发的材料和可外发公开材料设匹配对照，确保其他条件不先遮蔽差异。

所有配置共用 Host 基础提示、模型、工具定义、预算、初始状态及 Oracle。若需要
不同策略，逐项记录差异。现代任务对齐/内容分类基线优先于决赛加入，以固定适配
实现比较；主论文数值不与本机数值直接排列。

先冻结代码（格式检查先完成）、依赖、任务/意图/工具划分、模型、提示、配置、
预算和成功条件，再运行。M9 的验证/测试已暴露，M10 是 TRAIN，只作开发/复现。
AgentDojo 也要区分适配开发与最终评测任务，声明公开预训练重合不可排除。

全矩阵先一轮；预先选定的六个核心任务加入两个消融，并追加两轮，使核心配置总计三轮。可形成
144 次主配置任务运行、48 次初轮消融、240 次核心重复，共 432 次任务运行的预算上限；
每次任务最多六次主 Host 模型请求，则最多 2,592 次主 Host 请求。分类/子 Agent
调用也计入统一 Provider 预算，在运行前另确定总请求及 Token 上限，不能无限追加。
这是计划规模，未运行前不计成绩。先根据剩余额度冻结可承受规模，出错/额度耗尽
保留未尝试分母，不事后删掉失败或用脚本填模型响应。

三来源×七绕过至少 21 个覆盖单元，五种效果与长链另设索引；这是覆盖矩阵，不是
宣称每个单元均为独立攻击意图。确定性回归支持全矩阵，代表任务用真实模型运行。

指标分开：

- 实际攻击成功、真实泄露/修改/执行、越权提议及真正网关阻断；
- 正常任务、攻击下任务、合法危险证据及授权高风险操作完成；
- 内容误报、动作误拦、ASK 数量、信息损失、恢复次数；
- 来源/调用证据覆盖、延迟、Token、超时、格式错误、执行结果未知。

模型自评不作主 Oracle。文件、Receiver、进程、Git ref、Memory 状态与上游
任务条件分别检查；关键事实命中和全文业务质量分列。按基础任务聚类汇总/区间，
重复次数不当作独立任务数。零成功的小样本也需说明区间和代表性限制。
